Architecture & UX Design

Cloud Agent Sandbox

Kiến trúc cloud an toàn để AI agent chạy code, duyệt web và thao tác file.

Cách đọc báo cáo: bắt đầu bằng bốn câu hỏi của đề bài bên dưới. Mỗi phần lần lượt cho biết agent làm gì, hệ thống bảo vệ ra sao, người dùng nhìn thấy gì và kết quả cuối có an toàn không.

1

Agent làm việc ở đâu?

Code và Browser chạy trong hai Firecracker microVM riêng, không dùng chung filesystem hoặc socket.

2

Điều gì giữ an toàn?

Network mặc định bị chặn; credential ở ngoài sandbox; file phải qua quarantine và scan.

3

Điều gì được lưu?

Plan, workflow, file version, receipt và audit được giữ; RAM, token và file tạm bị xóa.

4

Khi nào user quyết định?

Ngay trước upload, gửi, xóa hoặc hành động bên ngoài có hậu quả.

microVM = máy ảo nhỏ, cô lậpControl Plane = bộ điều phối đáng tin cậy Quarantine = khu cách ly fileTyped action = hành động có cấu trúc rõ ràng Outbox = sổ ghi ý định và kết quả
  • Production dùng hai Firecracker microVM riêng cho Code và Browser.
  • Trusted Control Plane sở hữu policy, workflow, approval, credential, state và audit.
  • Network default-deny; không có route tới control plane, metadata hay private network.
  • Credential dài hạn luôn ở ngoài sandbox.
  • Browser và Code không có shared filesystem, direct socket hoặc direct edge.
  • Artifact phải được quarantine và scan trước export/upload.
  • External side effect chỉ xuất phát từ typed Action Executor.
  • Hành động nhạy cảm cần canonical human approval gắn với exact action.

Mặc định phải cô lập

Guest kernel, filesystem, identity và quota độc lập.

Agent không tự cầm quyền

Credential Broker giữ token; Executor thực hiện typed action.

Có thể dừng và phục hồi

Checkpoint, version, outbox và receipt cho recovery an toàn.

User quyết định đúng lúc

Chặn tại điểm mở rộng quyền hoặc side effect.

Hệ thống hoạt động như thế nào?

Trước tiên hãy đọc luồng sáu bước. Ba sơ đồ phía sau giải thích chi tiết cùng một luồng; danh mục 24 thành phần nằm cuối phần để tra cứu.

Chi tiết kỹ thuật — đọc từng sơ đồ độc lập

a) Một yêu cầu đi từ user đến kết quả như thế nào?

Hai microVM làm việc riêng. File đi vào khu scan; kết quả scan quay về Control Plane trước khi export được phép.

b) Ai kiểm tra và cấp quyền cho hành động?

Policy đánh giá risk, Approval ghi nhận quyết định, Broker cấp quyền ngắn hạn, Executor hành động và Outbox lưu dấu vết.

c) Credential đi đâu — và không đi đâu?

Secret thật ở Vault/KMS. Sandbox chỉ dùng opaque handle; token ngắn hạn chỉ được gắn vào exact request của Action Executor.

03 · Trust Boundaries

Ranh giới nào bảo vệ người dùng?

Mỗi vùng quy định rõ thứ gì được đi vào, thứ gì được đi ra và thứ gì tuyệt đối không được vượt qua. Prompt của agent không phải security boundary.

1. User & UI · trusted intent surface

Inside
Goal, plan preview, canonical approval, review.
Allowed

Never
Untrusted webpage không được giả làm system UI.

Inside
Identity, workflow, policy, audit, brokers, state index.
Allowed
Typed command, capability, result và manifest.
Never
Không mount workspace hoặc parse/execute artifact với privilege.

3. Code microVM · untrusted

Terminal, package tools, CoW workspace.
Allowed

Không credential dài hạn, metadata route hay Browser socket.

Untrusted parser, scanner và detonation process.
Allowed
Artifact staging vào; scan result + manifest ra.
Never
Artifact chưa đạt policy không được export.

6. Persistent Storage

Workflow, versions, receipts, manifests, audit.

Never

7. External Internet & APIs

Gateway-inspected read hoặc approved typed action.
Never

8. Credential Boundary

Vault/KMS, refresh token, token exchange.
Allowed

Never
Không long-lived secret trong sandbox, model, logs hay snapshot.
04 · Execution & Security Model

Bốn lớp bảo vệ chính

Hệ thống không chỉ “tin agent sẽ làm đúng”; mỗi lớp kỹ thuật giới hạn một loại rủi ro khác nhau.

A. Execution

  • Dual Firecracker microVM
  • Signed read-only base image
  • Copy-on-write workspace
  • Non-root execution
  • CPU/RAM/PID/disk/time quotas
  • Clean warm pool
  • Separate identities

B. Network

  • Default-deny egress
  • Controlled DNS
  • SSRF/metadata protection
  • Re-evaluate redirect/DNS
  • Method/body/domain policy
  • DLP và upload control
  • No proxy bypass

C. Credential & Action

  • Secret outside sandbox
  • Opaque credential handle
  • Short-lived/downscoped token
  • Audience-bound request
  • Canonical typed action
  • Policy + exact approval
  • Outbox + receipt

D. Artifact

  • Quarantine staging
  • MIME/archive validation
  • AV/YARA/policy scan
  • Suspicious-file detonation
  • Manifest + hash
  • Policy-controlled promotion
05 · State Persistence

Sau khi phiên kết thúc, điều gì còn lại?

Thông tin cần cho review và resume được lưu; dữ liệu có thể chứa secret hoặc malware bị xóa hay revoke.

Persisted

  • Task plan, workflow, policy version
  • Approval receipt
  • Workspace versions và file diff
  • Artifact manifest
  • Idempotency/outbox record
  • External receipt và immutable audit
  • Browser profile chỉ khi opt-in

Deleted after session

  • Process state và RAM
  • /tmp và clipboard
  • Transient downloads
  • Non-persisted browser profile

Revoked / never snapshotted

  • Live sandbox capability
  • Short-lived access token
  • Plaintext/long-lived secret
  • OTP/password
  • Raw hidden model reasoning
  • Unscanned quarantine content

External side-effect state

Cách đọc: đường trên là trường hợp bình thường. Nếu external service không trả lời rõ ràng, hệ thống đi xuống trạng thái unknown, kiểm tra receipt rồi mới kết luận; không tự upload lại.

Unknown mutation không được retry mù. Hệ thống query provider receipt hoặc reconcile thủ công. Workspace commit dùng versioning và compare-and-swap.

Auto-allow

Public read-only web trong plan; selected files; reversible workspace changes; pinned packages từ approved mirror.

Require approval

New domain/package; new credential scope; upload; email/form; delete/overwrite; publish; expanded filesystem/network; payment/permission/security settings.

Giảm fatigue bằng auto-allow cho thao tác low-risk, batch theo plan + destination + data class, scope hẹp có TTL, và “deny + explain” khi policy không chắc. Không có “always allow” cho hành động rủi ro cao.

MVP dùng công nghệ đơn giản hơn nhưng giữ nguyên ranh giới an toàn và cách user phê duyệt.

Production là kiến trúc đích. MVP giữ nguyên trust boundaries và typed broker interfaces để có thể thay runtime mà không thiết kế lại security model hoặc UX.

11 · Security Invariants

Mười luật an toàn không được phá vỡ

Nếu một thiết kế hoặc thay đổi vi phạm bất kỳ luật nào dưới đây, nó không được đưa vào production.

Long-lived plaintext credential không vào sandbox, model context, logs, screenshots hoặc snapshots.
Sandbox không có route tới control plane, metadata hoặc private network mặc định.
Không egress path nào bypass gateway và DNS policy.
External side effect cần typed action, policy verdict và approval receipt khi áp dụng.
Approval bind exact destination, data, action và expiry.
Unknown external mutation không bao giờ được retry mù.
Post-user snapshot không được reuse cross-tenant; unscanned snapshot không resume.
Unscanned artifact không bao giờ rời quarantine.
Control Plane không parse hoặc execute untrusted artifact với privilege.
Pause, stop và credential revoke phải có hiệu lực nhanh và được audit.
